# Shellbell changelog

This overview tracks the computer, relay and mobile release lines separately.
Package changelogs are generated by Changesets when versions are prepared.
See [versioning and release rules](docs/versioning.md).

## Unreleased

### Computer

- Start installed iTerm2, tmux or Herdr from the phone when no session is open;
  distinguish startable backends from connected ones and bound startup requests.

- Mirror iTerm2, tmux and Herdr sessions through encrypted device connections.
- Native macOS controller and Linux archive tooling keep desktop and headless
  service lifecycles separate.
- Support secure v2, authenticated WebRTC cutover, explicit encrypted relay
  fallback and bounded request outcomes without automatic input replay.
- Require reserved Mac candidate build numbers, derive native marketing versions
  from the bundled service, and align Linux downloads with computer release tags.

### Relay

- Shared authentication, pairing, revocation, notification policy and bounded queues
  run through Cloudflare adapters or one Node process with private SQLite storage.
- Direct FCM and APNs providers replace Expo Push Service.
- Connection lifetime, admission, storage mappings and Node lifecycle refactors
  preserve ciphertext routing and atomic notification budgets and claims.
- Self hosting guides cover Cloudflare, Docker with TLS, backup and recovery,
  organizational operations and the requirements for other runtime adapters.

### Mobile

- Move Settings to a header gear, add a small Shellbell mark and installed
  version/build information, and remove donation links.
- Explain terminal scaling, show disabled font controls while scaling is automatic,
  and keep Reading mode as the wrapped-text view.
- Show all supported terminal backends in a session picker, including cold startup
  actions, availability guidance and creation failures.

- Negotiate WebRTC in normal connections and show the committed terminal route and connection progress.
- Pause terminal streaming and input after direct loss; relay terminal fallback requires an explicit temporary choice.
- Keep the keyboard visible when tapping terminal quick keys so the first tap sends the key.

- Enable Android release R8 optimization, obfuscation and unused-resource shrinking.
- Keep CocoaPods outside Fastlane's Ruby bundle while preserving native build configuration.
- Include the notification extension bundle name required by App Store validation.
- Report TestFlight compliance or testing-state blockers after upload before assigning a build to testers.
- Keep live terminal status rows visible below the cursor through keyboard and
  viewport changes, including bottom alignment for small source grids.

- Reconnect on Wi-Fi/cellular handoff, show phone offline state separately from
  computer or relay outages, and retain unsent drafts while disconnected.

- Keep every mobile route above system navigation when the keyboard is closed.
- Add optional WebGL rendering with DOM fallback and native HTTP(S) link opening.

- Native Android and iOS notification paths support encrypted private context.
- Per computer relay settings preserve local pairing keys.
- Version metadata now uses the existing native `0.1.0` baseline consistently.

### Release preparation

- Require owner discussion and approval for major upgrades. Check source versions
  and queued release plans against recorded major ceilings before preparation.

- Target mobile 1.0.0 for the launch release train. Beta candidates keep the
  numeric marketing version and use their channel and platform build number for
  identity; computer and relay versions remain independent.

- Add explicit local build-and-upload lanes for Play internal testing and internal
  TestFlight groups; failed builds cannot upload previous artifacts.

- Independent release lines, relay version alignment, explicit native build
  numbers, compatibility and recovery notes define the release process.
- Check each component's source tag, distinguish prepared versions from shipped
  artifacts, and provide a release note template for platform availability and
  qualification.
- Documentation and version checks guard source metadata and local links.

There is no public release entry yet. Local builds, hosted test deployments and
device observations are recorded in the [current qualification](docs/before-first-release.md#qualification-status)
and [release checklist](docs/before-first-release.md). Broader WebRTC network qualification,
physical iOS, signed distribution and an independent security assessment remain
open.
