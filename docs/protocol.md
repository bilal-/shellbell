## Envelope

Every WebSocket frame is binary CBOR (`cborg`, with `{ ignoreUndefinedProperties: true }` so
optional fields never appear on the wire), except protocol-level ping/pong control frames (agent
keepalive) and the literal text frames `"ping"` / `"pong"` (phone keepalive while
foregrounded). Every decoded object is validated with zod before use; invalid frames are dropped
(agent/app) or close the socket with `4400` (relay).

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "v": {
      "type": "number",
      "const": 1
    },
    "t": {
      "type": "string",
      "enum": [
        "ctrl",
        "e2e"
      ]
    },
    "from": {
      "anyOf": [
        {
          "type": "string",
          "pattern": "^[a-z2-7]{26}$"
        },
        {
          "type": "string",
          "const": "relay"
        }
      ]
    },
    "to": {
      "type": "string",
      "pattern": "^[a-z2-7]{26}$"
    },
    "seq": {
      "type": "integer",
      "minimum": 0,
      "maximum": 9007199254740991

  },
  "required": [
```

For v1, `to` is required when `t` is `"e2e"`. `seq` is used by `e2e` frames only (`ctrl` frames
send `0`). For `e2e` frames, `body` is `{ n: bytes(24), c: bytes }`; for `ctrl` frames it is
one of the Ctrl messages below.

## Experimental v2 opaque relay carrier

The relays can route this versioned envelope between already authenticated paired endpoints.
Its `body` is an opaque encoded v2 session frame, limited to 61,000 bytes. There is no outer
JavaScript-number sequence counter. Owner test builds can opt into v2 bootstrap and direct transport. Default new-pair
connections still use v1; upgraded pairs require v2. See `docs/architecture/direct-transport-wire-v2.md`.

## Experimental v2 route coordination

After mutual Noise confirmation and durable v2 floor persistence, encrypted relay
frames carry bounded CBOR arrays: `["shellbell-v2-route-payload", kind, body]`.
The kind is `terminal` (at most 59,000 bytes), `signal` (at most 30,000 bytes),
or `control` (at most 512 encoded bytes). Total plaintext is limited to 60,000 bytes.
Only the committed route admits terminal records. Signaling and the four-phase
prepare/prepared/commit/committed exchange use the authenticated relay session.
A direct candidate requires verified native DTLS and fresh Noise keys. An ambiguous
commit closes routes; recovery uses a fresh relay session and never replays input.

## Byte limits

Enforced before decoding. Exceeding a limit closes the socket with `4413`.

| Socket state | Max frame |
|---|---|
| unauthenticated | 4096 B (4 KB) |
| any `ctrl` frame | 16384 B (16 KB) |
| `e2e` from phone | 65536 B (64 KB) |
| `e2e` from agent | 1048576 B (1 MB) |

## Rate limit

Core-handled control and encrypted messages use a per-socket token bucket of
**60 messages/s, burst 200**. Exceeding it closes the socket with `4429`.
WebSocket protocol-level ping/pong frames are outside core admission. Literal text
`"ping"` / `"pong"` keepalive is adapter-handled: Cloudflare uses platform
auto-response, and Node replies before the core bucket. Node frame/queue limits
still apply; [heartbeat rate admission](architecture/extensibility.md#relay-heartbeat-admission)
remains an explicit hardening task.

## Private notification context v1

Capability: `notify-context-v1`. Never enable until native delivery and encrypted
enrollment are acknowledged. Legacy peers continue receiving `notify` alerts.
Each recipient box is AES-256-GCM ciphertext with a random 12-byte nonce and an
appended 16-byte tag. Only a notification-specific derived key decrypts it.
HKDF-SHA256 input is K_pair; salt is UTF-8 `shellbell-notification-v1`; info is
UTF-8 JSON array `[computerFp, phoneFp, generation]`; output is 32 bytes.
Generation is canonical unpadded base64url of 16 random bytes.
AAD is UTF-8 JSON array `["shellbell-notification-v1", computerFp, phoneFp,
generation, sessionId, eventId]`. Inner routing fields must equal outer fields.

Plaintext limit: 1536 UTF-8 bytes, including JSON.
Ciphertext limit: 1552 bytes, including tag.
Sequence is canonical positive decimal u64. Native receivers additionally check
recipient identity, generation, expiry, revocation and per-session replay state.
Notification boxes never share terminal connection keys or sequence counters.
Schema refinements reject control/bidi/lone-surrogate labels, noncanonical byte
encoding, invalid time windows and aggregate size overflow.
